# File Tabs

Paper-style folder tabs over a package of static documents kept together, like tabbed dividers in a binder: a grant application, a plot lease, a year of meeting minutes. Each tab is a standalone document; they share one panel, with optional controls and a busy status at the header's end.

For code files, use [Code Block](../../content/code-block/page.mdx) or [Demo](../../content/demo/page.mdx): they render their headers with File Tabs.

```tsx
import {
  FileTabs,
  FileTabsControl,
  FileTabsList,
  FileTabsPanel,
} from '@fairgarden/design/navigation/file-tabs'
```

`FileTabs` holds the selection and the header's settings (`frame`, `controls`, `status`, `mono`). `FileTabsList` renders the header from them: 56 px with its rule, the tabs across its whole width under 12 px of room and standing on the rule, and the status and controls at its end. `FileTabsPanel` is the one tabpanel, labelled by the selected tab. The selected tab takes the text-bearing selection fill, edge and label, marked by weight too, and its radii grow while it's pressed; each label reserves its bold width, so selecting a tab never moves the row. Hover underlines the other labels. Labels take the UI face at the caption size and are never caps; `mono` sets them in mono for file names, as Code Block and Demo do. It needs no docs engine, so it works anywhere.

The header opens a host: a bordered box with no padding, a `--primary1` face and no clip, such as a code block's frame, or the `FileTabs` root given a frame class, as in these demos. The host keeps the page's panel radius, `--radius-2-25`; the tabs alone take the paper-tab radius, `--radius-2-75`, and their curves leave the host's side line below its corner. The tab strip runs out over the host's side edges by their width, so there's no gap between an end tab and the edge, and the edges are drawn again over the header, so scrolled tabs and the ends of the strip's scrollbar pass under them. `frame` says which host it is: `"top"` (the default) for the top of a box with rounded corners, `"joined"` for a part below another, and `"none"` for no box at all.

In print the header hugs its labels: plain labels in a wrapping row, the selected one in bold, without the controls or status.

## Tabs or File Tabs?

[Tabs](../tabs/page.mdx) switch between views or sections of one thing on a page: settings panes, the sections of an article, filtered views of one list. File Tabs hold a package of separate documents kept together, where each tab is a standalone document, drawn as paper tabs. For code files, use [Code Block](../../content/code-block/page.mdx) or [Demo](../../content/demo/page.mdx), which use File Tabs for their headers.

## Controls

import { DemoFileTabsControls } from './demos/controls'

<DemoFileTabsControls.Title />

`controls` go at the header's end. A `FileTabsControl` is the one to use for a menu: render it as the Menu's trigger (`<Menu.Trigger render={<FileTabsControl />}>` from Base UI) with an `Icon` inside (the ⋮ is `more_vert` at the tag tier, `size="tag"`) and an `aria-label`. It always hangs just outside the host's end edge, whatever the number of documents, and takes no room from the tabs: an ear 20 px wide from the frame's line, from its top edge to the foot of the header's rule. Its 44 px hit area reaches out into the gutter, never over the tabs. Pointing at it or focusing it outlines the ear at once, on a soft fill; its tooltip keeps its own delay. At the top of a rounded frame the outline wraps the frame's corner: it runs along the frame's arc and end edge, so ear and corner read as one shape. A document menu holds actions such as print, download and copy link; a copy confirms with a [Toast](../../feedback/toast/page.mdx), never in the header. Small icon Buttons, the other kind of control, sit in the header instead, beside a single document's label.

**Leave room for it.** Nothing measures the space: the host must leave `--fgd-size-file-tabs-control` (24 px) free past the frame's end, with nothing clipping it sideways, or an `overflow-clip-margin` that covers it. Where the page ends sooner than the 44 px hit area, clip the page sideways (`overflow-x: clip`) so the rest of it can't scroll the page. This site's column keeps that gutter at every width, 44 px from the medium breakpoint. Both columns below keep it: the first on the page, the second inside a column that clips, with the gutter inside its clip.

## Many documents

import { DemoFileTabsOverflow } from './demos/overflow'

<DemoFileTabsOverflow.Title />

Any number of documents fits. When the tabs overflow, the row scrolls sideways with the browser's own scrollbar. The header keeps its height whatever the scrollbar takes: a scrollbar that takes room hangs flush under the header's rule, over the panel's top, and one that overlays the page shows over the foot of the tabs. Either way the tabs never lift off the rule. At either end of the scroll the end tab sits flush with the frame's edge.

## Status

import { DemoFileTabsStatus } from './demos/status'

<DemoFileTabsStatus.Title />

`status` is the busy "-ing…" label while something the header started is under way, such as "Saving…". It's laid over the header's end beside the controls, covering the end of the tabs on the frame's face rather than pushing them, so they never move. It's a live region, mounted whenever `status` is set: pass `''` while idle rather than leaving it out, so the change is announced. Confirmations don't go here: a copied link, say, shows a toast.

## Frames

## Mono labels

`mono` sets the labels, and a single document's label, in mono (`type-data`) for file names, e.g. code. [Code Block](../../content/code-block/page.mdx) and [Demo](../../content/demo/page.mdx) set it; the geometry is the same in either face.
